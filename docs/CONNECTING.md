# Connecting: toolchain and dev-loop recipes

This machine has no `ANDROID_HOME` / `JAVA_HOME` set globally, and we do not set them globally
either. Every command below sets them per-invocation.

## SDK / JDK locations (this machine)

- Android SDK: `D:\Software\Android-SDK` (platform-tools, build-tools 36.0.0, platforms/android-37.0,
  emulator). A second SDK at `C:\Program Files (x86)\Android\android-sdk` has cmdline-tools and
  android-35/36 — only needed if Gradle demands an older platform than 37.
- JDK: Android Studio's bundled JBR at `D:\Software\Android\jbr` (OpenJDK 25). Tried first; if
  Gradle rejects JDK 25 for this Android Gradle Plugin version, stop and report rather than
  installing a separate JDK.
- `adb`: `D:\Software\Android-SDK\platform-tools\adb.exe`.

## Per-command environment (PowerShell)

```powershell
$env:ANDROID_HOME = 'D:\Software\Android-SDK'
$env:JAVA_HOME = 'D:\Software\Android\jbr'
$env:Path = "$env:ANDROID_HOME\platform-tools;$env:JAVA_HOME\bin;$env:Path"
```

Run this in the same shell/session before `npm run prebuild`, `npm run android`, `npm run
apk:release`, or any `adb`/`gradlew` invocation.

`android/local.properties` (git-ignored, regenerated by prebuild) must contain:

```
sdk.dir=D\:\\Software\\Android-SDK
```

Never commit `android/local.properties` — it is machine-specific and is covered by `android/` in
`.gitignore` (the whole `android/` directory is Continuous Native Generation output).

## Verify a device is attached

```powershell
& "D:\Software\Android-SDK\platform-tools\adb.exe" devices
```

Plug in a phone with USB debugging enabled, or start an emulator from Android Studio, before
running `npm run android`.

## Dev loop

```powershell
npm install
npm run prebuild   # expo prebuild --platform android --clean
npm run android    # expo run:android — builds + installs the dev-client build
npm run start      # expo start --dev-client — Metro only, once the dev-client is installed
```

## Connecting the app to a local `hermes serve`

`hermes serve --host 127.0.0.1 --port 9119` binds loopback only. The server rejects WebSocket/
REST peers that are not loopback when bound to `127.0.0.1`, and any non-loopback `Host` header
forces gated auth — so for local dev we forward the phone's own loopback to the host's loopback
instead of using the host's LAN IP:

```powershell
& "D:\Software\Android-SDK\platform-tools\adb.exe" reverse tcp:9119 tcp:9119
```

With the reverse tunnel in place, the app on the phone can dial `http://127.0.0.1:9119` /
`ws://127.0.0.1:9119` exactly as if it were running on the host — the peer-address check on the
server sees a loopback connection, and `?token=` mode (dev only) works without gated auth. This
is why token-mode is dev-only: it only works when the server considers the peer to be loopback,
which in production means a real TLS-terminated remote host with the password or Portal OAuth
flow instead (see the auth matrix in `project-planning/implementation-plan/README.md`).

Read the session token the way the desktop app does — see
`../hermes-agent/apps/desktop/electron/dashboard-token.ts` and `hermes_cli/web_server.py` around
`_SESSION_TOKEN` / `HERMES_DASHBOARD_SESSION_TOKEN` in the upstream checkout. Never paste the
token into a commit, log, or milestone file.
