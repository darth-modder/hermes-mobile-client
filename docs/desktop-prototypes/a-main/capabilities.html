# Systematic Debugging

## Overview

Guessing at fixes wastes time and hides the real fault. Find the root cause
before changing any code.

## The four phases

1. Root cause: read the whole error, reproduce it, check what changed.
2. Pattern: find a similar path that works and list the differences.
3. Hypothesis: change one thing at a time and predict the result.
4. Fix: write a failing test first, then make the smallest change.

## Red flags

- "Let me just try…" before you can explain the failure
- Three failed fixes in a row: stop and question the design
