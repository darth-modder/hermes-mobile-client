## Escalate to Fable (hard decisions)

**Resolved 2026-09-07.** All five items below were decided; see `DECISIONS.md` (D3 build path,
D2 session reap, D4 tool artifacts, D1 device policy and M03 criterion, D5 read-only gate). The
original text is kept for the record.

1. **Build path.** Keep WSL2 builds (working, slow, extra machine state), diagnose the Windows
   AF_UNIX failure (firewall/EDR/platform), or move to EAS cloud builds. Affects M12 release
   signing and every developer's setup.
2. **Server-side session reap on disconnect.** `ws_orphan_reap` fired immediately after a
   clean close. Decide whether M07's lifecycle keeps the socket open through short backgrounding
   (fight the reap), or embraces reclaim-on-reconnect keyed by stored session id (current M03
   behavior). Requires reading `tui_gateway/session_reaper.py` and `tui_gateway/ws.py` upstream.
3. **Untracked tool artifacts** (`.agents/`, `.claude/`, `.zcode/`, `skills-lock.json`): ignore,
   commit, or delete.
4. **Test device policy.** M03 was proven on an emulator. Decide whether physical-device runs are
   required before a milestone can be marked done (M04 cookie persistence, M07 doze, M08 Custom
   Tabs redirect, M11 push all behave differently on real hardware).
5. **Any deviation from the auth matrix or the "hermes-agent is read-only" rule.** If Sonnet or
   Opus concludes a milestone cannot be met without an upstream change, stop and escalate; do not
   file an upstream PR or edit the checkout.

## Verification protocol for Opus (applies to every milestone)

1. Read `AGENTS.md`, the tracker `README.md`, and the milestone file.
2. Re-run every command in the milestone's Verification log yourself. Paste your own output
   under a new heading `### <date> — Opus re-verification` in the same file.
3. Re-run every on-device exit criterion as written in the **original** criterion text, not as
   the implementer reinterpreted it. If an interpretation differs, record both and mark the
   criterion `partially verified` with the gap named.
4. Review the code the milestone added against `AGENTS.md`: no browser globals in
   `src/upstream/**` or `src/gateway/**`; no token logging; no `close_on_disconnect: true`;
   reauth only on 401/403; secrets only in SecureStore; pinned dependencies.
5. Only Opus changes a tracker status to `done`. If a check fails, set the status back to
   `in-progress` and append a `## Verifier findings` section listing each failure with the exact
   command and output. Do not fix implementation bugs yourself unless the fix is one line and
   obviously correct; otherwise hand findings back to Sonnet.
6. Upstream gate (decision D5): `git -C ../hermes-agent rev-parse HEAD` equals
   `src/upstream/UPSTREAM.json.commit`, and `git -C ../hermes-agent status --short` lists nothing
   under an allow-listed path from `scripts/sync-upstream.mjs`. Other entries in that checkout are
   out of scope. Either condition failing is a hard failure.
7. Commit verification notes separately from implementation commits, message prefix `verify(M0N):`.
